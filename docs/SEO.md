# SEO and metadata

Everything here is generated from `src/content/site.json` — change the facts in
one place and the head tags, sitemap and structured data follow.

## Canonical origin

`site.json` → `url`. It is a placeholder (`https://yousefabdulaziz.com`) until
the real domain is attached: set `SITE_URL` at build time or edit the JSON, and
canonical tags, Open Graph URLs, `sitemap.xml` and `robots.txt` all update.

```bash
SITE_URL=https://example.dev npm run build
```

Each route declares its own canonical. The root route deliberately does not, so
the 404 page ships without one instead of claiming to be the home page.

## Per page

| Route             | Title                                  | Canonical          |
| ----------------- | -------------------------------------- | ------------------ |
| `/`               | `Yousef Abdulaziz — Frontend Engineer` | `/`                |
| `/projects`       | `Work — Yousef Abdulaziz`              | `/projects`        |
| `/projects/$slug` | `<project> — Yousef Abdulaziz`         | `/projects/<slug>` |
| `/about`          | `About — Yousef Abdulaziz`             | `/about`           |
| `/contact`        | `Contact — Yousef Abdulaziz`           | `/contact`         |
| 404               | root title                             | none               |

Every page carries `og:type`, `og:site_name`, `og:title`, `og:description`,
`og:url`, `og:image` (1200×630), `twitter:card: summary_large_image`, the same
title/description pair for Twitter, `color-scheme`, and two `theme-color` tags
that follow `prefers-color-scheme`.

## Structured data

One `Person` entity in the root head (`application/ld+json`):

```json
{
  "@type": "Person",
  "name": "…",
  "jobTitle": "…",
  "url": "…",
  "email": "mailto:…",
  "address": { "@type": "PostalAddress" },
  "sameAs": ["https://github.com/usefmahmud"],
  "knowsAbout": ["…"]
}
```

Project pages do not add `CreativeWork` markup on purpose: the case pages have
no dates, ratings or prices to describe, and inventing fields is worse than
omitting them.

## Sitemap and robots

Both files are generated by `scripts/gen-sitemap.mjs` on `prebuild`, from
`site.json` + `projects.json` — they cannot drift from the content.

```
public/sitemap.xml   # home, work index, about, contact + one URL per project
public/robots.txt    # allow all + Sitemap: <origin>/sitemap.xml
```

## OG image

`public/og.png` (1200×630, 72KB) is a rendered HTML card, committed as a static
asset so no build step needs a headless browser.

To regenerate after a copy or palette change:

```bash
cp scripts/og/template.html public/og.html      # template needs the fonts route
npm run build && PORT=3123 node server.mjs &
# open http://127.0.0.1:3123/og.html at 1200×630 and screenshot to public/og.png
rm public/og.html
```

The template uses the same four font files and the same tokens as the site, so
the card cannot drift from the design.
